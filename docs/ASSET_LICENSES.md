# Visual Asset Inventory and Licenses

## Scope

This file records every visual asset shipped or committed by the Stage 10 pixel-archive UI.

The runtime application does not download visual assets from a third-party host. It does not include BOOTH product images, copied scenario thumbnails, external fonts, YWBY files, Pixelarticons files, Kenney files, GIFs, audio, or cursor assets.

## YWBY handling record

Referenced only as a design-direction research source in Issue #83:

- https://x.com/YWBY_GG/status/2035714691759214961
- https://www.postype.com/@ywbygg/post/21913245

Binding restrictions recorded by the project include no redistribution, no commercial use, no AI training, and no retouching.

Repository rule:

- no YWBY file or byte sequence is committed;
- no file is hotlinked, mirrored, resized, recolored, sprite-sheeted, traced, hashed into a replacement, or used to create a derivative;
- no YWBY file appears in runtime output, package output, screenshots, public directories, or Git history;
- the Stage 10 art is independently constructed from basic geometry and the written design requirements.

## Release checklist

Before merging any visual change:

1. list changed visual/runtime asset paths;
2. confirm every asset is project-owned or has a commercial-compatible distribution license;
3. search for YWBY filenames, URLs, binary copies, and derivatives;
4. confirm no runtime `http://` or `https://` image/font request;
5. run the local-only Playwright network assertion;
6. inspect generated desktop and mobile screenshots;
7. update this file when the asset inventory changes.
